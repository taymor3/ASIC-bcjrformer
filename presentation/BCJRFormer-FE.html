BCJRFormer ASIC / Front-end design

From read windows to decoded logits

The ASIC inner decoder turns pre-windowed noisy reads into one signed logit per encoded position.

  • M = reads, N = positions, L = M × N tokens, F = input features, D = model width.
  • H = attention heads, K = encoder layers. Token index t = m × N + n.

System / Transaction flow

One controller sequences the frame

A committed parameter image can serve successive frames. The host sends the features first, then the padding mask.

  • Transfers happen when valid and ready are both high. A stalled producer holds its valid and payload.
  • The shared memory fabric accepts one transaction at a time, retains its requester, and returns the read value or write acknowledgment.

Stage 1 / Architecture

Embed each input token

Normalize the input features, project them to model width, and normalize the projected vector.

  • The output tensor has L rows and D columns. Stage 1 visits all L tokens.
  • The two norms have separate learned parameters and use the same LayerNorm hardware.

Stage 1 / RTL

Copy and reuse token workspaces

embedding_ctrl sequences copies and service commands. Each operation finishes before its consumer starts.

  • Shared layernorm_ctrl normalizes TOKEN and VECTOR in place. Shared linear_ctrl writes VECTOR using dot_engine.
  • Copy phases use READ and WRITE issue/wait states. The final X write acknowledgment gates RESPONSE.

Stage 2 / Architecture

Add position and read identity

Each scalar in X receives one position embedding and one read embedding.

  • The logical expression is (X[t,j] + P[n,j]) + E[m,j]. The intermediate result is narrowed before the second add.
  • Stage 2 preserves the L × D shape and visits padded tokens too.

Architecture · position_sequencer

Stage 2 / RTL

Use one local adder twice

position_ctrl instantiates position_sequencer and position_add_unit. The sequencer holds the running value and parameter operand.

  • Each addition widens the signed operands, then saturates back to signed 16-bit with 10 fractional bits.
  • The loop advances j, then n, then m after write acknowledgment. The last acknowledgment gates RESPONSE.

Stage 3 / Architecture

Refine X with K encoder layers

Each pre-norm layer mixes information across tokens, then applies a feed-forward network to each token.

  • For each head, attention scales QKᵀ by 1/√(D/H), applies row softmax, and weights V before the output projection.
  • The FFN maps D → 4D → D with GELU between linear maps. Each layer returns L × D.

Stage design · layer_ctrl

Stage 3 / RTL

Reuse one layer controller K times

encoder_ctrl sends a layer-specific parameter descriptor and waits for layer_ctrl to complete before incrementing k.

  • U is reused for LN2 after attention and residual 1. R remains in X until its token’s second residual is written.
  • For each token, FFN writes FFN_HIDDEN, replaces it with GELU activations, then writes VECTOR for residual 2.

Stage 3 / RTL detail

Attention works one head and query at a time

attention_ctrl waits for the Q, KEY, and VALUE banks to finish, then visits each (head, query) pair.

  • SCORE, EXP and PROB are row workspaces. The weighted-value controller writes the head slice of Z.
  • MASK applies to the query here. Padded queries use uniform probabilities. Ordinary queries normalize across all L keys.
  • Output projection starts after every Z slice commits and finishes after all ATTN_OUT writes.

Stage 4 / Architecture

Project each token to a scalar logit

A learned D-to-1 affine map turns each encoded token into a signed score.

  • Weights and bias are shared across tokens. The result contains L logits in flattened read/position order.
  • The affine head runs on padded tokens too. Stage 5 uses MASK to decide which scores contribute.

Stage design · final_ctrl

Stage 4 / RTL

Reuse the shared linear and dot engines

final_ctrl dispatches one linear descriptor per token. Its source is X at t × D and its destination is LOGIT at t.

  • linear_ctrl supplies the parameter bias and weight pointers. dot_engine sends term products through mac_unit.
  • The shared linear response follows the committed logit write. final_ctrl waits for all L responses.

final_ctrl · linear_ctrl · dot_engine

Stage 5 / Architecture

Average only valid reads

At each encoded position n, aggregate across m using the original padding mask.

  • The same set of unpadded logits drives both the sum and the count. The output has N entries.
  • If Cₙ = 0, aggregation returns EMPTY_POSITION with the first empty n. The core suppresses the whole output frame.

Stage design · aggregation_ctrl · core_ctrl

Stage 5 / RTL

Release outputs after the final write

aggregation_ctrl scans MASK and LOGIT for each n, then uses the shared reciprocal service for scaling.

  • A padded mask skips the LOGIT read. Valid logits update sum_q and count_q together.
  • For Cₙ > 0, multiply by the fixed-point reciprocal and round/saturate to the output word. Clear sum and count for the next position.
  • The core reads OUTPUT and holds each logit, index and last flag through host backpressure after successful aggregation.

Evidence / Front-end status

Ten trained frames matched the integer reference

The lab reported 1,440 of 1,440 exact RTL logit matches against fixed-point Python.

  • Frame 00 matched in Windows CXXRTL and lab Xcelium. Lab VCS matched frames 01–09. Reported completion was cycle 1,533,280,239 with rounding status and no saturation.
  • The trained fixture used (F, M, N, D, H, K) = (27, 1, 144, 96, 8, 6) and 687,991 parameter words. The ten frames were unpadded and single-read.
  • Fixed-point Python and saved PyTorch bit decisions matched at 1,431 of 1,440 positions. Trained multi-read and padded coverage remain open.
  • The lab mapped the small (2, 2, 2, 2, 1, 2) practice design and saved an initial floorplan. Trained-design synthesis, SRAM selection and physical sign-off remain open.
