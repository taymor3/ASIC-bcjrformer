\section{Conclusions}
BCJRFormer was studied as a digital inner-decoding workload, implemented as a five-stage SystemVerilog core, and evaluated through two separate experiments. The architecture makes the boundary explicit: the host loads trained parameters and prepared inputs, while the core returns indexed logits using shared compute and a memory-backed schedule. Ready/valid transactions and committed-write barriers coordinate data and control. The fixed-point description identifies where precision, approximations, and rounding affect the computation.

Ten trained-model frames matched all \(1{,}440\) fixed-point reference words in SystemVerilog simulation. The dated fixtures add evidence for arithmetic, internal writes, and selected controller behavior. The small-core synthesis exercise demonstrated library mapping and exposed a LayerNorm setup limitation at the 20\,ns target. The logged 200\,ns result met its synthesis constraint with a narrow setup margin. The small core was then placed and routed in Innovus. After revising the clock target to 300\,ns and fixing four slew violations, slow setup and fast hold passed with zero failing paths. Innovus physical checks passed, and the team exported the GDS and matching source netlist \cite{backend}.

\subsection*{Next verification steps}
Extend trained-model evaluation across additional read counts and padding cases. Complete foundry-deck DRC and LVS for the exported core and obtain power measurements. Implement and verify the full trained configuration separately. A broader decoding evaluation should report target-bit performance and integer-to-RTL agreement separately.
